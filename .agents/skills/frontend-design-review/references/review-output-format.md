# Review Output Format

## Frontend Design Review: [Component/Feature]

### Context
- Purpose
- User
- Primary task
- Visual direction
- Technical constraints

### Summary
State what is ready and what is not without hiding uncertainty.

### Design system
- Existing component/pattern reused where possible
- Design tokens used
- Variants/states covered
- Deviations documented

### Pillars
- Frictionless: task flow and action hierarchy
- Quality Craft: design-system fit, visual quality, accessibility
- Trustworthy: state transparency and actionable errors

### Issues

**Blocking**
1. Issue + evidence + required fix

**Major**
1. Issue + evidence + recommended fix

**Refinement**
1. Optional improvement

### Verification
Record the runtime/screenshot/accessibility checks actually performed.
