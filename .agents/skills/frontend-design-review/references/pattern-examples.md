# Pattern Examples

## Good
- Clear task hierarchy with one dominant action.
- Intentional visual direction grounded in the product.
- Reused components with semantic tokens.
- Keyboard-accessible states and visible focus.
- Errors that explain what happened and what the user can do.

## Avoid
- Generic card-grid UI without information hierarchy.
- Hardcoded colors/spacing that bypass the design system.
- Decorative motion that competes with the task.
- Color-only status indicators.
- Happy-path-only implementations with no degraded/offline/error states.
